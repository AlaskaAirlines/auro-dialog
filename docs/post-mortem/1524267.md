# AB#1524267 — Documentation Refactor: Multi-Page Structure and UI/UX Guides

**Branch:** `jjones/modernizeDocs/AB#1524267`
**Scope:** Documentation-only. ~41 files changed. Split the monolithic `docs/partials/{api,index}.md` into a multi-page documentation structure (`docs/pages/*.md` plus topic-scoped partials), added eight demo pages, vendored a client-side markdown renderer (`demo/support/demo-support.js`), authored getting-started guides for React and Svelte, and wrote UI/UX guides (design, accessibility, keyboard-behavior, VoiceOver, why-dialog). No component/runtime source was changed.

---

### Section 1 — The Problem

The `auro-dialog` docs were a flat pair of partials — `docs/partials/api.md` and `docs/partials/index.md` — rendered into a single README/demo page. This had several shortcomings:

- **No UX guidance.** There was no material on when to use a dialog, accessibility expectations, keyboard behavior, or screen-reader (VoiceOver) behavior.
- **No framework getting-started.** Consumers integrating with React or Svelte had no reference for registration, TypeScript typing, or state management.
- **Single-page sprawl.** All content lived in one page with no navigation, making the growing API + usage material hard to scan.

---

### Section 2 — Decision: Multi-Page Structure via `pages.json` + Generated-Content Markers

The docs were restructured into discrete pages under `docs/pages/` (`index`, `getting-started`, `api`, `customize`, `design`, `accessibility`, `keyboard-behavior`, `voiceover`, `why-dialog`), each with a matching `demo/*.html` shell and a `demo/pages.json` manifest that drives the top page-nav.

- Each page is authored as HTML scaffold (`contentWrapper > nav > mainContent > scrollWrapper`) with `auro-nav`/`auro-anchorlink` anchor navigation.
- Reusable prose is factored into topic-scoped partials (e.g. `docs/partials/getting-started/react.md`) and inlined into pages via `AURO-GENERATED-CONTENT` `FILE:`/`CODE:` markers, expanded at build time by the auro-cli docs build.
- Marker nesting is kept to one level (accordion wrappers live in the page; leaf partials are included directly) because the pinned published auro-cli has no second expansion pass.

---

### Section 3 — Local Demo Renderer (`demo/support/demo-support.js`)

AuroDocsSite renders demo markdown with a unified/remark/rehype pipeline, not `marked.js`. To make the rich `docs/pages` markup (embedded HTML + GFM tables + fenced code) render identically in the local `npm run dev` demo, a renderer was vendored into `demo/support/demo-support.js`.

- It was **vendored** from the Auro formkit `@aurodesignsystem/utils/demo-support` module because that module is a private, unpublished workspace package and cannot be installed in a standalone component repo.
- The remark/rehype stack is loaded from the jsDelivr ESM CDN, consistent with the other CDN imports in the demo HTML files.
- It also injects the top page-nav from `pages.json` and adds copy-to-clipboard buttons to code blocks.
- **XSS considerations:** the input is the repo's own trusted docs markdown. Rendered output is moved into `<main>` via `DOMParser` + `replaceChildren(...)` rather than `innerHTML`, which keeps the write explicit and lets custom elements upgrade on connection. (Confirmed clean in PR code review.)

---

### Section 4 — Flush-Left Authoring Constraint

The `docs/pages/*.md` files must be authored **flush-left (column 0)**, with code samples as fenced blocks surrounded by blank lines.

- **Why:** the remark pipeline treats any HTML line indented ≥4 spaces as an indented code block. Deeply-nested page scaffold (`contentWrapper > mainContent > section > accordion`) authored with natural indentation would collapse — accordions and headers would silently disappear.
- The whitespace-stripping transform that would otherwise allow indented authoring exists only in an **unreleased** auro-cli (workspace `0.0.0`); it is **not** present in the published auro-cli this repo pins (checked 3.6.0 and 3.7.1) nor in auro-library (5.12/5.13). On the current published toolchain the final flush-left form must be authored by hand.
- Validation: render `demo/*.md` through the pipeline and confirm `<auro-accordion>`/`<auro-header>` counts match the intended structure.

### Section 5 — Getting-Started Framework Guides (React 19 / Svelte)

Getting-started guides were written for React and Svelte, both leaning on native custom-element support (React 19; Svelte's built-in custom-element handling) rather than wrapper libraries.

- **React JSX typing (React 19):** the initial draft used the pre-React-19 `declare global { namespace JSX }` augmentation. React 19 removed the global `JSX` namespace (types moved under the `react` module), so the global form is silently ignored under the modern automatic runtime. The guide was corrected to augment `declare module 'react'`, with a note to target `'react/jsx-runtime'` when `"jsx": "react-jsx"` (the React 19 default) does not pick up the module augmentation.
- **Fenced-code languages:** TypeScript declaration blocks and the JSON `tsconfig` block were initially fenced as ` ```js `; corrected to ` ```ts ` / ` ```json ` so syntax highlighting is accurate.

### Section 8 — Second Review Round Findings

A follow-up `/code-review` on the updated PR head ran **single-model on Opus 4.8 again** (Sonnet 5 still not enabled on this deployment), so the 🟡/📄 items below are single-model / unconfirmed. It surfaced one new blocker plus two nits:

- 🔴 **`demo/demo-nav.css` is untracked.** All ten demo shells `<link>` `./demo-nav.css` — the styles for the injected page-nav and code-block copy buttons (Section 3) — but the file is matched by `.gitignore` line 7 (`demo/*.css`) and was never committed (`git cat-file -e HEAD:demo/demo-nav.css` fails; `git check-ignore` confirms it is ignored). It exists only on the author's working copy, so on a fresh checkout the nav and copy buttons render unstyled. **Root cause:** the `demo/*.css` wildcard is intended for *generated* demo CSS, but `demo-nav.css` is a **hand-authored source file** that got swept up by it.
  - **Formkit contrast:** auro-formkit does not hit this. Its ignore targets only `components/**/demo/*.min.css` (built output), and the `#page-nav` styling is sourced from the shared `@aurodesignsystem/config` `demo-styles.scss` package (bundled into a generated `styles.min.css`), not hand-copied per component. The `demo-nav.css` here was a hand-copy mirroring that shared package.
  - **Remediation options:** (a) *pragmatic* — negate the rule (`!demo/demo-nav.css` in `.gitignore`) and `git add -f demo/demo-nav.css` so the source file is tracked; or (b) *formkit-aligned* — consume `@aurodesignsystem/config` demo-styles and narrow the ignore to `*.min.css` (larger structural change, better as a follow-up ticket).

- 📄 **"native `toggle`" wording corrected.** The React and Svelte getting-started guides described `toggle` as the "native" event. auro-dialog dispatches a plain `new Event("toggle")` in `componentBase.js` (`dispatchToggleEvent`, a custom-dispatched event) — **not** the platform-native `ToggleEvent`, which carries `oldState`/`newState`. Reworded to "the component's `toggle` event" in `docs/partials/getting-started/react.md` and `svelte.md`. The described behavior (fires on close; `addEventListener('toggle', …)` / `ontoggle` work) was already accurate — only the word "native" was imprecise. (The generated `demo/getting-started.md` is gitignored/untracked and regenerates from these partials, so it needed no hand-edit.)

- 🟡 **`chore: update dependencies` commit lacks an `AB#`/`#121` reference** (single-model, unconfirmed). The prefix itself is correct (only `package.json`/`package-lock.json` changed); the commit message just needs a work-item/PR reference. Left for the author to amend.

### Key Lessons

1. **On the published auro-cli, multi-page component docs must be authored flush-left.** The indentation-stripping transform lives only in an unreleased CLI; ≥4-space indentation silently becomes an indented code block and collapses the page scaffold. Validate by counting rendered `<auro-accordion>`/`<auro-header>` elements.

2. **React 19 removed the global `JSX` namespace.** Custom-element typing must augment `declare module 'react'` (or `'react/jsx-runtime'` under the automatic runtime), not `declare global`. The old pattern fails silently rather than erroring.

3. **Keep commit prefixes matched to content.** Dependency bumps riding along on a docs branch belong in their own `chore:` commit — reviewers (and changelog tooling) key off the prefix.

4. **Vendoring the AuroDocsSite renderer is the right call for standalone-repo demos.** The formkit demo-support utility is unpublished, so local demos must reproduce the unified/remark/rehype pipeline (not `marked.js`) to render the same rich markup the published docs site uses. Render into the DOM via `DOMParser` + `replaceChildren`, not `innerHTML`.

5. **Distinguish hand-authored demo assets from generated ones in `.gitignore`.** A broad `demo/*.css` ignore silently swallows hand-written demo CSS, and the file goes missing on a fresh checkout with no error. Prefer ignoring only generated output (`demo/*.min.css`, as auro-formkit does), and source shared demo chrome (page-nav, copy buttons) from the `@aurodesignsystem/config` demo-styles package rather than hand-copying it per repo. If a hand-authored file must live under an ignored glob, negate it explicitly (`!demo/demo-nav.css`) and verify with `git check-ignore` / `git cat-file -e HEAD:<path>` that it actually landed in the tree.

6. **`auro-dialog`'s `toggle` is a custom event, not the native `ToggleEvent`.** It is dispatched as `new Event("toggle")` (bubbles, non-cancelable) and carries no `oldState`/`newState`. Docs should call it "the component's `toggle` event," not "native." Listeners still attach normally via `addEventListener('toggle', …)` or `ontoggle`.
